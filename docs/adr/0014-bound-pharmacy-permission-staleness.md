# Bound pharmacy permission staleness

The identity service checks current session and user state on its own requests, while the pharmacy API currently authorizes a locally verified token whose role can remain stale for roughly 24 hours. Pharmacy writes and sensitive reads, including customer-identifying sale history, bill items, and receipts, must reflect session revocation, account deactivation, and role changes within 60 seconds. The identity service should expose a dedicated session/role verification contract; the pharmacy API may cache its result by session ID for no more than 30 seconds, without sharing the identity service's Redis or database. Every cached result must remain bound to the verified user, system, and tenant/client ID of the signed token; mismatches are rejected rather than authorized from another session or tenant. Once that cached result expires, the pharmacy API must stop confirming writes and sensitive reads if identity status cannot be verified. A cashier may retain an attempted sale locally as pending, but it is not a confirmed sale. Ordinary catalog reads may continue under a valid signed token during an identity-service outage.
