# Resolve offline sale conflicts explicitly

Separate retryable delivery failures from business conflicts during offline sale replay. Preserve the original payload and stop automatic retry for a conflicted entry. An authorized person must resolve or cancel it with a recorded reason; neither silent discard nor endless retry is an acceptable outcome for an unconfirmed sale. The `PendingSales` module owns this: network failures, identity outages, 5xx, 401, and 403 leave a sale pending for automatic sync; any other refusal makes it a conflict with the server's reason. A person may retry a conflict, or an ADMIN+ user abandons it with a reason, which pharmacy-api records (its ADR-0009) and after which the same request is refused. A recorded sale whose KY forms were refused is KY pending until they are recorded or closed with a reason the same way.
